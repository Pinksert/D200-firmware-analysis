# 尼康 D200 官方固件 A/B 段解析（明文）

> **一句话结论**：D200 属于 **D2X 那一「老代」**，并不是 D300 那一「新代」。
> 它与 D300 的**代码几乎不共用**（A 段 32 字节块交集只有 **48 块**），
> 但**一批素材资源是共用的**——内置示例图里有 **30 张** 在 D200、D2X、D300 三台之间逐字节完全相同（SHA256 一致）。
> 换句话说：传承给 D300 的，主要是机身外壳和一批老素材；里面的程序几乎全部重写了。

本仓库存放尼康 D200 官方固件（版本 **A/B 2.01**，B 段日期 `2008/08/18`）的拆分结果，
以及一份不依赖任何逆向工具即可复现的拆分 / 校验脚本。所有结论均来自**二进制逐字节比对**与**说明书交叉印证**。

## 姊妹项目

本系列对尼康同一时期几台机型的官方固件做「明文」拆解（即不破解、只解析已公开的官方固件）：

- **D90 固件解析（明文）**：https://github.com/Pinksert/D90-firmware-analysis
- D300 / D300S 的同类仓库见同一账号下的 `D300-firmware-analysis`、`D300S-firmware-analysis`。

D200 的特殊之处：它是 D300 **前一台**上市的机型，但两者之间**隔着整整一代**平台——
这篇就是把这件事用固件证据钉死。

## 处理器平台

尼康这一代固件是**两段式**架构，必须分开说：

- **B 段（主控）**：全机型都是 **富士通 FR 系列**——32 位 RISC、大端、16 位定长指令，
  二进制里带有 `FUJITSU` / `ITRON` / `Softune` 字符串。
- **A 段（协处理器，负责 IO）**：**跨代会换架构**。
  - 老代（D2X / **D200**）：**不是 FR**（FR 的特征指令如 `0x9720` 出现 **0 次**），
    具体内核未坐实，只确定是某款日立系 16 位定长内核。
  - 新代（D300 / D3 / D700 / D90 / D300S）：A 段才是 FR。

⚠️ 网上常说的「尼康用富士通 FR」**只对 B 段成立**；A 段在老代根本不是 FR。

## 固件分析报告

### 1. 总体结论

1. **代际归属**：D200 与 **D2X 同代（老代）**，与 **D300 不同代（新代）**。六项独立指标零例外（见第 4 节）。
2. **代码共用度极低**：
   - A 段（协处理器）：D200 ∩ D300 的 32 字节块交集仅 **48 块**
     （分母 D200 7,486 / D300 14,930，约 **0.64%**）——几乎不共用。
   - B 段（主控）：D200 ∩ D300 交集 **9,616 块 = 11.41%**（分母 D200 84,307 / D300 122,505）。
   - 对照：D300 ∩ D3 的 A 段交集 2,968 块、B 段 43.33%——D300 与 D3 才是「近亲」。
3. **资源却共用**：
   - 内置示例图：D200 有 33 张、D2X 33 张、D300 34 张，其中 **30 张 SHA256 完全相同**。
   - 时区城市表相同；影像合成（Overlay）清单里 D200 同时出现在 D2X / D300 / D3 三家固件中。
   - 结论：共用的是**素材/资源**，不是**程序代码**。

### 2. 校验和（CRC16/XMODEM）

每段末尾 2 字节是该段载荷的 CRC16/XMODEM 校验和：

| 段 | 算法 | 计算值 | 文件末 2 字节 |
|----|------|--------|---------------|
| A 段 | poly=0x1021, init=0x0000, 大端 | `0xEF19` | `0xEF19` ✅ |
| B 段 | 同上 | `0xE25F` | `0xE25F` ✅ |

> 用本仓库 `split.py` 可一键复现上述校验；它是「文件有没有被改过」的金标准。

### 3. 各段解析

- **A 段（256 KB，协处理器）**
  - 基地址 `0x80000`，负责 IO 协处理。
  - 内含机型日期 **`2008/06/09`**，比 B 段版本串的 `2008/08/18` **早 70 天**——A/B 两段并非同一天定稿。
  - 与老代一致：A 段**没有大块明文界面文本**（实测 0 KB），UI 文案以其它形式存放。
- **B 段（3.75 MB，主控）**
  - 基地址 `+0x40000`，承载 UI 与影像处理。
  - 老代特征：B 段**不含**新代那种大块明文界面字符串（D300 有约 540.8 KB 可提取 UI 文本，D200 为 0 KB）。
  - 富士通 FR 内核，带 `FUJITSU` / `ITRON` / `Softune` 标识。

### 4. 横向对比：老代(D2X/D200) vs 新代(D300/D3/D700/D90/D300S)

下列**六项指标两两成对**，D200 每次都站在「老代」一侧，零例外：

| # | 指标 | 老代（D2X / D200） | 新代（D300 等） |
|---|------|-------------------|----------------|
| ① | 体积 | A 256KB + B 3.75MB | A 512KB + B 7MB |
| ② | A 向量表位置 | `@0` | `@0x7FC00` |
| ③ | 未用中断填充 | `FFFFFFFF`（D200 119 条 / D2X 111 条） | 兜底 `0x000FE250`（D300 ×210 / D3 ×215） |
| ④ | A 版本块位置 | `@0x200` | `@0x000` |
| ⑤ | B 段 FirmwareSignature 前 12 字节 | `55 AA F8 FF FF FF F8 FF FF FF` | `00 14 xx xx`（末 4B = ASCII 机型标签 Q220/Q260/D300/Q340） |
| ⑥ | `HI8-2600` 字符串 | 仅出现在 D200 A`@0x3888`、D2X A`@0x380a` | 不存在 |

### 5. 平台汇总

- **B 段（主控）**：全机型都是富士通 FR。
- **A 段（协处理器）**：老代（D2X / D200）**不是 FR**；新代（D300 等）才是 FR。
- 判代际**只看 A 段**；跨机型不要做「代码同源」式比对（不同协处理器内核无可比性）。

### 6. 规格对照（来自说明书规格页 `D200_NT(Sc)08` p203–206）

| 项目 | D200（老代） | D300（新代） |
|------|--------------|--------------|
| 传感器 | CCD | CMOS |
| 有效像素 | 1020 万 | 1230 万 |
| 对焦模块 | Multi-CAM1000，**11 区** | 3500DX，**51 点** |
| 原生 ISO | **100–1600** | 200–3200 |
| 连拍 | 5 fps | 6 fps（MB-D10 手柄达 8 fps） |
| 屏幕 | 2.5 吋 / 23 万点 | 3 吋 / 92 万点 |
| NEF | 仅 12-bit | 12/14-bit，三种压缩 |
| 存储卡 | CF 单槽 | CF I/II 单槽 |
| 机身 | 147×113×74 mm / 830 g | 147×114×74 mm / 825 g |
| 语言 | **13** 种 | 15 种 |
| GPS | 支持（MC-35） | — |

> 常见误区：① D300 **不是双卡槽**（CF+SD 是 D300S）；② D300 **没有虚拟水平线**；
> ③ 原生 ISO 下限是 D200 更低（100 起），D300 是 200 起。

## 可复现方法

```bash
# 1) 拆分整体固件并校验 CRC（会写出 A2000201.bin / B2000201.bin）
python3 split.py

# 2) 仅校验已有的 A/B（不写出）
python3 split.py --check
```

所需的全部输入都在本仓库：`D200_0201.bin` 是官方升级文件本身，
`split.py` 不依赖任何第三方逆向工具，只做「按已知偏移切分 + CRC16/XMODEM 校验」。

横向对比的分析，可用各机型官方固件二进制与对应说明书 PDF 做交叉印证。
